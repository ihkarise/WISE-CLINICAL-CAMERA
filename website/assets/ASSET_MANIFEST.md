# WISE Clinical Camera — Website Asset Manifest

The single index of every visual asset the website uses: what it is, where it
is used, its dimensions, its source, and how to replace it. A machine-readable
copy is [`assets.json`](./assets.json) (kept in step with this file).

**Golden rule — one brand, one source of truth.** The logo, app icon and brand
mark are the *same* aperture used by the Flutter app (`tool/gen_icons.py`,
`lib/shared/widgets/wise_logo.dart`). The web copies are generated from the same
geometry by `tool/gen_web_assets.py`, so the website and the app never drift.
Do **not** hand-edit the generated PNGs — change the generator and re-run it.

To drop in a new asset: put the file in the matching folder below, keep the
documented filename, and (for screenshots/posters) match the aspect ratio. No
HTML edit is required for the slots already wired up.

## Empty slots (reserved folders)

`app/`, `store/`, `documentation/` are reserved for future owner-provided
assets (in-app promo art, store listing graphics, doc figures). They are empty
by design; nothing references them yet, so the site builds without them.

---

## Replacing an asset — checklist

1. Put the file in the correct folder, keeping the documented filename.
2. If you changed a file extension, update `index.html` and `assets.json`.
3. Optimize rasters (resize to display size; prefer WebP/AVIF; keep originals
   elsewhere — do not commit multi-MB source files).
4. Run `python3 tool/validate_website.py` — it fails if a referenced asset is
   missing.
