# Asset Slots

Assets the specifications reference but that were never supplied with the
repository. Each has a documented fallback, and **no placeholder art is
committed** — a placeholder logo that reaches a store listing is worse than an
obvious gap.

See [SPECIFICATION_CONFLICTS C-014 and C-015](../SPECIFICATION_CONFLICTS.md).

## Adding fonts

1. Drop the `.ttf` files into `assets/fonts/`.
2. Uncomment the `fonts:` block in `pubspec.yaml`.
3. `flutter pub get`.

Nothing in the code changes: `WiseTokens.fontFamily` already names `Poppins`,
and the fallback chain simply stops being used.

**Do not add `google_fonts` instead.** It fetches font files over the network at
runtime, which would breach offline-first (PRD §30) and the network policy
(Privacy §31).

## Adding the icon and splash

Both need per-platform sizes. Whether that is generated by a tool or produced by
hand, the source art belongs in `assets/branding/` and the generated output in
the platform directories.

---

## A note on placeholders

It is tempting to commit a placeholder icon so the app looks finished. The
failure mode is that a placeholder ships. An obviously missing asset gets
supplied; a plausible-looking wrong one does not.
