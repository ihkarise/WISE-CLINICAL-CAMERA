# `test_data/` — real-world CV validation

Phase 2 §15. This directory is the intended home for the real-image validation
that the synthetic suites cannot provide.

## Nothing here is committed

**No clinical photograph is in this repository, and none should be added.**

Every image directory below is `.gitignore`d. If real clinical data is used for
validation it must be de-identified and used with appropriate authorisation, and
it stays on the machine doing the validation.

What *is* committed is the structure, the manifest schema, and the results — so
that a validation run is reproducible and its findings are reviewable without
the images travelling with them.

## Why this exists

Everything in `docs/cv/THRESHOLDS.md` today comes from synthetic imagery
generated by `test/support/cv_dataset.dart`. Those results characterise the
algorithm under controlled distortion. They are not clinical accuracy, and per
Phase 2 §14 they must never be described as such.

Two questions can only be answered with real photographs:

1. **Does the confidence model mean anything on real tissue?** The synthetic
   benchmark shows confidence tracking *feature survival* rather than
   *alignment correctness* — at 1.2× scale the transform is recovered exactly
   and still scores POOR. Whether that mis-ranking matters in practice depends
   on what real skin, hair and dressings do to the feature count.
2. **Where does alignment actually fail?** Synthetic distortion is uniform.
   Real failure is not: specular highlight on moist tissue, a dressing that
   moves between visits, hair regrowth, a limb rotated out of plane.

## Layout

```
test_data/
  reference_pairs/    BEFORE/AFTER pairs of the same site, same subject
  quality_cases/      single images exercising lighting and focus judgement
  calibration/        images containing a scale reference of known size
  manifests/          committed: what each case is and what it should do
  results/            committed: what actually happened, per run
```

## Manifest schema

One JSON file per case set, in `manifests/`. Images are referenced by filename
and checksum, never embedded.

```json
{
  "case_set": "wound-healing-series-a",
  "authorisation": "how consent/authorisation was obtained",
  "deidentification": "what was removed and how it was verified",
  "cases": [
    {
      "id": "a-001",
      "before": "reference_pairs/a-001-before.jpg",
      "after": "reference_pairs/a-001-after.jpg",
      "sha256_before": "...",
      "sha256_after": "...",
      "expected_status": "good",
      "notes": "same site, 14 days apart, dressing removed in both"
    }
  ]
}
```

`expected_status` is the human judgement of whether these two images *should*
align — it is the ground truth the engine is scored against. It is a clinician's
call, not the algorithm's.

## Running a validation

There is no runner yet, and writing one before there is data to run it on would
be premature. When the data exists, the validation belongs alongside
`test/cv/alignment_benchmark_test.dart`, which already emits the table format
the results should use, and must be skipped by default so that CI on a machine
without the data stays green rather than silently passing an empty set.

## De-identification checklist

Before any image is placed here:

- [ ] Faces, tattoos, jewellery and other identifying marks outside the region
      of interest are cropped or masked.
- [ ] EXIF is stripped. `MetadataAnonymizer` does this for exports; verify it
      independently for inbound data — a source file may carry GPS, device
      serial, or an owner name.
- [ ] Filenames carry no patient identifier, initials, hospital number or date
      of birth.
- [ ] Written authorisation exists and is referenced in the manifest.
- [ ] A second person has checked the above.
